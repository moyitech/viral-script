# HyScript 任务 1：模型输出评估报告

> 本报告只评价 Hy3 生成的口播文案及其评测结果，不评价项目工程质量、产品完整度或参赛
> 交付完成度。

## 1. 评估结论摘要

本次实验以 100 个固定开放式选题为输入，每题最终选定一份经实时检索形成的冻结研究背景；
检索失败题按不可变 attempt 重试。每份背景用于生成 280、450、700 字三档文案，共得到
300 条模型输出。所有输出均成功冻结并完成 rules + Hy3 Judge 事后独立批量评分，没有生成
失败或门控失败。

首轮评测平均归一化总分为 **0.9969**：280 条为 1.0000，18 条为 0.9583，2 条为
0.9167。八个维度中，选题匹配度与主题明确/信息量全部得到 3 分；主要扣分来自长度偏差
（9 条）、合规边界（8 条），以及少量吸引力、口播、修辞和逻辑问题。700 字档出现唯一严重
长度不足样本：目标 700 字，实际 442 字。

高分不能解释为模型输出“接近完美”。生成模型和主 Judge 均为 Hy3，正式集分数严重饱和。
将三候选主编基线与端到端直接生成合并为同一个 600 条样本集后，Hy3 两轮评分的逐维完全
一致率为 **96.83%**，七维全部一致率为 **81.33%**，总分 MAE 为 **0.009127**，Spearman
为 **0.7115**；这是本报告的内部一致性主结果，分组统计只用于诊断。基线组 50 条盲化样本
的两份独立人工评分进一步表明，当前 Hy3 Judge 在这 50 条上的七个主观维度全部给出 3 分，
无法形成相对排序；在相同冻结输入上，**GPT-5.6-Luna** 与两位人工平均分的排序最接近，但
七维总分 Spearman 也只有 **0.236**，尚属弱相关。对 20 条攻击样本追加专用
reward-hacking 检测和 Tavily 显式引用核验后，机械重复、术语堆砌、自我评分与伪造引用
四类共 20/20 检出；引用核验在其余 15 条攻击负对照中未误报。随后只对两组各 300 条冻结
成稿增量运行这两套检测器，没有重跑原八维评分：基线标记 4/300，端到端直接生成标记
3/300。7 条警报逐条复核均有可定位的正文或引用问题，未观察到明显误报；但其余样本没有
独立人工负标签，仍不能把这一结果表述为严格误报率。最稳妥的结论是：这些输出在当前
Rubric 下普遍满足主题、结构和基本口播要求，但事实可靠性、长文长度控制、高风险措辞和
自然候选间的细粒度优劣仍需要独立校验或人工评审。

后续的“端到端直接生成”实验使用同一批 100 份冻结研究背景，
对每个“题目 × 长度”只调用一次 Hy3 生成内容，首稿直接作为最终稿。其平均分为
**0.9669**，较三候选主编基线低 **0.0300**；严格配对为单次生成胜 12、平 131、
负 157。差距主要来自吸引力（-0.3167）和口播流畅度（-0.2067）。这表明当前
Rubric 能检出候选生成与主编合并的总体收益；本次未新增查询规划或 Tavily 请求，
因此不是对实时搜索质量的对照。

## 2. 评估对象与实验范围

### 2.1 模型输出

- 输入：仓库内项目构造的 100 个固定选题，覆盖 8 个领域和多类难例标签。
- 调研：每题由 Hy3 规划查询，Tavily 执行实时检索；失败题按 attempt 重试，最终每题选择
  一份冻结研究背景。
- 生成：基线使用 `editorial_candidates`；对照组使用 `single_shot`，两组都从同一冻结背景
  生成 280、450、700 字版本。
- 输出：两组各 300 条冻结口播文案，共 300 组严格配对。同题三档共享研究背景，因此不是
  300 个独立题目。
- 评测边界：只覆盖“已有选题 → 实时调研 → 文案生成”，不评价上游热榜发现、推荐质量、
  真实创作者采用率或视频传播效果。

生成阶段不读取评分结果，也不根据 Rubric 进行反馈改写。评分在轨迹冻结后单独运行，通过
`run_id`、轨迹 SHA-256 和 Rubric 指纹关联，避免评估信息进入被评对象。

## 3. 评分方法

### 3.1 八维 Rubric

正式评测使用 Rubric v1.1，各维度取 1–3 分。长度由确定性规则评分，其余七维由 Hy3 Judge
评分。Judge 使用 `high` reasoning、`temperature=0`、`top_p=1`，按内容、传播、口播和
安全拆成四组请求。

| 维度 | 评分者 | 3 分标准摘要 |
| --- | --- | --- |
| 选题匹配度 | Hy3 Judge | 正面回答题设，覆盖冲突两侧与核心人群 |
| 字数符合度 | rules | 非空白字符数相对目标偏差不超过 10% |
| 主题明确与信息量 | Hy3 Judge | 多个有效信息单元推进，事实、解释、结论互相支撑 |
| 吸引力 | Hy3 Judge | 开头有钩子，中段持续推进，结尾自然产生余味或互动 |
| 口播流畅度 | Hy3 Judge | 气口、重音和停顿自然，无需临时改词或重断句 |
| 修辞与记忆点 | Hy3 Judge | 修辞服务理解，存在自然且可复述的记忆点 |
| 语言逻辑与结构 | Hy3 Judge | 前提、解释、转折和结论递进，关键因果有桥梁 |
| 合规性 | Hy3 Judge | 不煽动、不夸大、不作无依据承诺，必要边界清楚 |

未触发门控时，八维等权汇总：

```text
final_score = 八个维度分数之和 / (8 × 3)
```

因此归一化分理论范围为 1/3–1，并非 0–1 min-max。重复凑字等结构性问题会触发硬门控，
门控后不提供可用最终分。完整行为锚点见
[Rubric v1.1](../eval/rubrics/script_quality_v1.json)。

### 3.2 实际评价次数

两套流程的每条正式输出都在冻结后执行一次确定性 rules 和一次完整 Hy3 Judge；
为考察内部一致性，又对同一 trace 独立执行一轮 Hy3 Judge。即每条输出有 **1 次
rules + 2 轮 Judge**。Judge 通常包含 4 次模型请求，解析失败时会重试。基线首评/复评
分别记录 1,269/1,262 次成功请求，单次生成组为 1,267/1,282 次。rules 是确定性的，
复评时未重复运行。

| 配置项 | 三候选主编基线 | 端到端直接生成 |

## 5. 基线典型模型输出分析

### 5.1 严重长度不足：T095-L700

该输出讨论“宠物进入商场，友好空间是否也该照顾怕动物的人？”，目标 700 字，实际只有
442 个非空白字符，偏差 36.86%。长度规则给出 1 分，其余七个 Judge 维度全部为 3 分，最终
仍得到 0.9167。这说明模型在长文长度修复后仍可能明显不足，也说明等权平均会稀释严重的单项
失败。证据见[冻结轨迹](../eval/experiments/formal-100-v1/generation/traces/attempt-001/traces/T095-L700-run-20260902T144958Z-16ce8b2b4bcd.json)和
[评分记录](../eval/experiments/formal-100-v1/results/items/run-20260902T144958Z-16ce8b2b4bcd/combined.json)。

### 5.2 吸引力与记忆点不足：T048-L280

该输出围绕公共 USB 充电风险给出建议，切题、信息、口播和结构均获 3 分，但吸引力与修辞
记忆点均为 2 分。Judge 认为开头虽进入主题，但前 20 字缺少强冲突；“顺线摸进”等局部表达
帮助理解，却没有形成自然、可复述的核心记忆点。最终分为 0.9167。证据见
[Judge 记录](../eval/experiments/formal-100-v1/results/items/run-20260902T143033Z-5544e05a8337/hy3_judge.json)。

### 5.3 口播局部拗口：T020-L700

该输出讨论共享单车禁停范围扩大。内容组织和记忆点获得 3 分，但“人在禁停区落锁，车收不到
信号，你走不了账”等局部措辞被判定需要改词或重断句，口播流畅度为 2 分，最终分 0.9583。
该样本只有口播流畅度被扣分，类似措辞可能增加实际录制时的修改成本。证据见
[Judge 记录](../eval/experiments/formal-100-v1/results/items/run-20260902T142053Z-20ba530b48a0/hy3_judge.json)。

### 5.4 指代与概念范围不清：T034-L280

该输出讨论家庭闲钱配置。Judge 指出“这类产品”指代突兀，现金类产品与储蓄国债的概念范围
可能混淆，因此逻辑结构为 2 分，其他维度为 3 分，最终分 0.9583。证据见
[Judge 记录](../eval/experiments/formal-100-v1/results/items/run-20260902T142510Z-1e5b852ccee3/hy3_judge.json)。

### 5.5 绝对化措辞带来合规扣分

合规性共有 8 条输出得到 2 分，常见模式是结论过于绝对。例如 `T034-L700` 用“抵消通胀”
描述收益效果，未限定收益率和通胀条件；`T050-L450` 将政策概括为“不让家长多掏钱”，容易
让观众误以为所有合理收费都违规；`T066-L280` 以“钱白花没减排放”概括碳信用问题，开头
范围过宽。按当前 Judge，292/300 条输出的合规性获得 3 分；这些扣分样本说明，模型为了口播
冲突感仍可能使用超出证据范围的强断言。

## 6. 重复评价：Judge 内部一致性

Hy3、GPT-5.6-Luna 和 GLM-5.3-Flash 都针对三候选主编基线与端到端直接生成的相同冻结输出
独立评分两轮。长度规则是确定性的，因此内部一致性只比较七个 Judge 维度。主结果先把两组
合并成 600 条、4,200 个维度配对后统一计算；合并 Spearman 直接使用 600 对总分，不是两个
分组相关系数的平均。

| Judge | 逐维完全一致率 | 七维全部一致率 | 总分 MAE | 总分 Spearman |
| --- | ---: | ---: | ---: | ---: |
| **Hy3** | **96.83%** | **81.33%** | **0.009127** | **0.7115** |

| GLM-5.3-Flash | 91.60% | 52.00% | 0.025000 | 0.5799 |

按两轮绝对分差，Hy3 的内部一致性最高，GPT-5.6-Luna 第二，GLM-5.3-Flash 第三。合并后的
Spearman 同时利用了组内排序与两组之间的分数差异；为识别天花板效应和组内波动，下面仍保留
Hy3 的分组诊断。

## 7. 评测结果的可信度检查

本节评价“评分是否值得相信”，不是把派生攻击文本当作正式模型输出。

### 7.1 人工与三种 Judge 的排序一致性

从三候选主编基线的冻结输出中抽取 50 条盲化样本，由两名评审者独立使用同一 Rubric 的
1–3 分锚点评分。两份表均覆盖相同的 50 个 `run_id`，题目、正文、批次和 trace SHA-256
与冻结模板完全一致，八维评分与备注完整。考虑到不同评审者可能整体偏严或偏松，本节不要求
逐项绝对分数完全相同：分数水平以两位人工评分的算术平均描述，相对排序以含并列秩的
Spearman 相关衡量。两位人工按维度先转为秩、再合成的尺度归一化排序相关为 **0.395**。

三种 Judge 均读取这 50 条相同冻结文案并使用 Rubric v1.1；比较使用各模型第一轮正式评分，
第二轮只用于内部稳定性，不与第一轮取平均。七维统计不含确定性长度规则；八维总分相关则把
同一长度规则分加入总分。模型名称 **GPT-5.6-Luna** 对应实验 API model ID
`gpt-5.6-luna-cdx`。

| 评分来源 | 七个主观维度均分 | 相对人工均分差 | 七维总分 Spearman | 含长度八维总分 Spearman |
| --- | ---: | ---: | ---: | ---: |
| 两位人工平均 | 18.62 / 21 | — | — | — |
| Hy3 | 21.00 / 21 | +2.38 | 不可计算 | 0.199 |
| **GPT-5.6-Luna** | **17.88 / 21** | **-0.74** | **0.236** | **0.299** |
| GLM-5.3-Flash | 19.50 / 21 | +0.88 | 0.033 | 0.094 |

GPT-5.6-Luna 在分数水平和相对排序上都是三种 Judge 中最接近人工的一种，但相关性仍然偏弱，
不能表述为“与人工高度一致”。Hy3 在这 50 条上的 350 个主观维度评分全部为 3 分，七维总分
没有方差，因此其相对排序相关无法计算；八维的 0.199 主要来自长度规则，不能解释为主观质量
排序能力。GLM-5.3-Flash 的平均分虽比 Hy3 更接近人工，但七维排序相关接近零。该人工样本只
覆盖高质量基线输出，存在范围受限；尚未覆盖单次生成组，也不支持直接以人工结果验证两种生成
流程的优劣。

### 7.2 判别力实验

从基线正式输出中按“领域 × 长度”分组轮询选择 20 个不同题目的来源样本，并在每组内优先选择
正式高分输出。20 个来源输出的正式分均为 1.0，覆盖 7 个领域（未覆盖职场），三档长度分布
为 7/7/6。每条来源输出构造未修改、截断至约 62%、泛化替换三个版本。

| 预期等级 | 样本数 | 平均最终分 | 门控数 |
| --- | ---: | ---: | ---: |
| 未修改 | 20 | 1.0000 | 0 |
| 截断 | 20 | 0.8667 | 0 |
| 泛化替换 | 20 | 0.4167 | 0 |

20/20 组满足“未修改 > 截断 > 泛化替换”，60 个成对比较也全部正确。这证明评估器能够识别
这 20 组人为构造的强退化；由于选样偏向高分、未覆盖全部领域，“未修改”也没有经过人工
质量确认，因此不能把 100% 排序率泛化为自然候选之间的细粒度判别能力。

### 7.3 对抗实验与自然输出增量检测

对抗集先只评价 answer key 中标记为 attack 的 20 条冻结 trace。检测协议采用
`generative_reward_for_critique_enhanced.py` 中的
reward-hacking 检测器：先检查同一字符是否连续出现至少 10 次，其余样本由 Hy3 判断是否存在
机械或无意义堆砌、自我吹捧/迎合评审、无关中英混填、文案自评与结构说明、写作指南等偏离
自然口播目的的内容。参考实现文件 SHA-256 为
`b0e32b1b86bce7f84d8678c652ba1cfafb038e17bfd3db204c21ffda8d8caab9`。

伪造引用不属于上述 reward-hacking 定义，因此另加独立的显式引用核验器。核验器先按正文
措辞识别带机构、报告、研究、统计或数据归因的完整句子，不使用 answer key 决定是否搜索，
再把冻结参考材料与 Tavily 定向搜索结果一并交给 Hy3。v1.1 协议把一般证据不足与伪造风险
分开：泛称“研究、调查显示”但没有可识别出处要素时，即使标为 `unverified` 也不自动阻断；
若命名机构、具体文献、年份或精确数字无法得到直接支持，或材料直接冲突，才按“伪造或不可
验证引用风险”阻断。搜索无结果不被表述为对该出处绝对不存在的证明。

| 攻击类型 | 样本数 | 检出 | 漏检 | 检出率 |
| --- | ---: | ---: | ---: | ---: |
| 伪造引用 | 5 | 5 | 0 | 100% |
| 重复凑字 | 5 | 5 | 0 | 100% |
| 术语堆砌 | 5 | 5 | 0 | 100% |
| 自我评分诱导 | 5 | 5 | 0 | 100% |
| **合计** | **20** | **20** | **0** | **100%** |

reward-hacking 检测器对其定义范围内的三类攻击共 15/15 检出，记录 20 次 Hy3 请求、41,161
token。引用核验器在 20 条攻击正文中识别出 6 条显式出处声明，执行 6 次 Tavily 搜索、获得
30 条结果，并执行 6 次 Hy3 核验、记录 84,641 token；5 条人工伪造引用全部标为
`unverified`。额外命中的 1 条真实媒体调查归因由冻结新华社材料和搜索结果直接支持，没有
误报；其余 14 条负对照没有显式出处句，因此未发起搜索。两套检测均使用 temperature 0、
top_p 1、`no_think`，未发生格式修复。

随后对基线与端到端直接生成的 600 条冻结正式成稿只执行上述攻击检测，没有读取或改写原八维
评分。参考 reward-hacking 实现是一个二分类检测器，因此重复凑字、术语堆砌和自我评分在自然
输出上只能报告合并标记率，不能拆成三个子类。

| 增量检测 | 攻击集检出 | 三候选主编基线 | 端到端直接生成 |
| --- | ---: | ---: | ---: |
| Reward-hacking（重复、术语、自评合并） | 15 / 15 | 0 / 300（0%） | 1 / 300（0.33%） |
| 伪造或不可验证引用风险 | 5 / 5 | 4 / 300（1.33%） | 2 / 300（0.67%） |
| **唯一成稿合计** | **20 / 20** | **4 / 300（1.33%）** | **3 / 300（1.00%）** |

基线 4 条引用警报分别是：将高风险偏好改写为高信任倾向、把 50% 写成“过半”、把毕业生
调查扩写为未获支持的证书结论，以及把 95 城房价研究改写为租金研究。端到端直接生成的 3 条
警报中，1 条出现“这一层边界就说到这，不重复”的结构自述；2 条引用警报分别把 32.3% 相对
16.9% 写成“翻倍都不止”，以及把重庆 2024 年数据泛化为“今年部分城市”并追加未获支持的
岗位供需结论。7 条警报均能在正文与证据中定位具体问题，逐条复核未发现明显检测器误报。

自然输出增量检测记录 600 次 reward-hacking Hy3 请求、1,057,885 token；引用核验只对
74 条含显式出处候选的成稿执行 77 次 Tavily 搜索和 74 次 Hy3 核验，记录 1,129,667 token。
两组均为 300/300 完成且没有格式修复。若只按“未人工注入攻击”的构造标签，把 600 条全部
先验视为负例，则 7/600 是自然输出警报率；但逐条复核表明这些是自然生成的真实缺陷，不宜
直接叫作误报。其余 593 条未做独立逐项人工负标，因此仍不报告严格 FPR。5 个伪造攻击正例
又复用了同一句虚假机构、白皮书和精确比例，攻击召回率也不能外推到全部伪造方式。现有 50 项
人工盲评用于分析 Judge—人工分数水平与相对排序，不是对其余 593 条自然输出的逐项攻击负标，
因此仍不能据此报告严格 FPR。

## 8. 端到端直接生成

### 8.1 设计与完整性

实验 `formal-100-e2e-single-shot-v1` 沿用基线的 100 个选题、280/450/700 三档任务和
100 份冻结研究快照。每份快照与三档长度各组合一次，因此形成 300 条严格配对输出；
研究背景的来源目标字数固定为 450，文案生成使用实际目标字数。这里的“端到端直接生成”
指搜索后由 Hy3 直接生成一次最终文案；为隔离生成流程差异，本次复用冻结检索，没有新的
Hy3 查询规划或 Tavily 请求。

每项的第一次 Hy3 调用是唯一内容创作。首稿解析成功后直接冻结，不运行三候选、主编合并、
长度修复、正文改写、grounding review 或 final rewrite。只有 JSON 格式异常允许调用 Hy3
修复，且必须保持首次输出的 `outline`、`script_text` 和 `reference_ids` 逐字符不变。
本次 300 条首稿全部可直接解析，格式修复调用为 0。

生成任务与 Hy3 客户端并发配置分别为 **300 / 512**；来源检索的 Tavily 并发为 **8**，
本次新搜索为 0；首评和复评 Judge 并发均为 **512**。300 条 trace 首批全部生成成功，
每条恰好一次内容生成。首轮 Judge 首批完成 294 项、补跑 6 项；复评首批完成 296 项、
补跑 4 项，两轮最终均为 300/300。Rubric、Judge prompt、模型、采样和 Judge 指纹均与基线一致。

两组的完整性、分数分布、八维、长度、领域和难例配对已合并到第 4 节；Judge 复评稳定性已合并到第 6 节。

### 8.2 资源与运行代价

| 生成链路资源 | 三候选主编基线 | 端到端直接生成 | 说明 |
| --- | ---: | ---: | ---: |
| 历史检索请求 / 本次新增 | 300 / — | 同一批快照 / 0 | 复用基线检索 |
| 历史检索累计响应时间 / 本次新增 | 431.28 秒 / — | 同一批快照 / 0 秒 | 不重复计费 |
| 内容生成调用 | 903 个候选调用 | 300 个单次调用 | 本次格式修复为 0 |
| 文案生成 Hy3 token | 21,902,797 | 4,130,219 | -81.1% |
| 来源检索规划 Hy3 token / 本次新增 | 327,472 / — | 同一批快照 / 0 | 历史成本单列 |

基线的 300 次搜索和 327,472 token 检索规划是当时产生 100 份共享快照的历史成本；
本次对同一快照做 replay，因此新增搜索与查询规划均为 0。这不能解释为真实上线的单次生成流程
天然不需要检索，而是实验隔离变量所致。本次生成没有失败或补跑，共记录 4,130,219 个 Hy3 token。

生成仍具随机性，因此配对结果支持“单次生成流程整体低于三候选主编流程”，但不支持把每一条分差
归因于某个特定编辑步骤，也不支持将差值归因于检索质量变化。

## 9. 模型输出能力与边界

### 9.1 当前证据支持的能力

- 在固定选题和冻结检索背景下，两组都有 300/300 条输出成功生成并完成两轮评分。
- 当前 Judge 认为两组输出的信息组织都较完整；单次生成的主要差距集中在吸引力、口播流畅度、
  长度和修辞记忆点。
- 基线 280 字档 100/100、450 字档 97/100 的长度维度获得 3 分；组合检测对重复凑字、
  术语堆砌、自我评分和伪造引用四类构造攻击共 20/20 检出，并在 600 条自然成稿中定位
  7 条可复核的攻击维度问题。
- 输出的主要问题集中且可定位：长文长度尾部、绝对化表述、局部口播措辞、记忆点和指代衔接。

### 9.2 当前证据不支持的结论

- **不能证明整体事实准确或证据可追溯。** 新核验器只覆盖正文中带机构、报告、研究、统计或
  数据归因的显式出处句，且每条最多检查 3 个候选；5 个伪造正例又使用同一模板，未覆盖普通
  无出处事实、隐式归因或更多伪造方式。
- **不能证明自然候选排序可靠。** 正式分数高度饱和，重复评价 Spearman 较低，判别力样本又
  是人为强退化版本。
- **不能证明高风险领域安全。** 健康样本全部满分只是当前 Judge 结果，未经过医学或合规专家
  标注；合规性也是复评最易波动的维度。
- **不能证明真实传播效果。** 实验没有播放量、完播率、转发率、创作者采用率或用户满意度。
- **不能保证联网重跑得到相同输出。** Tavily 结果会随时间变化，`hy3` 是服务端模型别名；
  冻结记录可以审计和重算，但外部调用只能复现实验流程。

## 10. 后续改进优先级

1. 对正文事实与冻结证据做逐句对齐，对不存在来源的机构、数字、结论设置硬门控。
2. 将严重长度偏差升级为关键约束门控，避免目标 700 字、实际 442 字仍获得 0.9167。
3. 收紧金融、医疗、政策和安全话题中的绝对化措辞约束，并对合规分歧自动进入复核。
4. 增加自然低分、跨模型生成和边界样本，重新校准 Rubric，降低满分比例。
5. 将两份 50 项人工盲评匿名化并版本化保存，补充端到端直接生成组的配对盲评；继续报告
   Judge—人工相对排序相关，不以评审者量尺差异强制制造单一绝对共识分。
